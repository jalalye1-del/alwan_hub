# قواعد التجاوب وربط لوحة التحكم

هذه القواعد معتمدة لكل واجهة أو ميزة جديدة في مشروع ألوان.

## الأجهزة المستهدفة

- Android وiPhone: واجهات مدمجة تعمل من عرض 320 نقطة فأعلى.
- الأجهزة اللوحية: أعمدة ومسافات أكبر دون تكبير مبالغ فيه.
- الويب: محتوى محدود العرض مع زيادة عدد الأعمدة بدل تمديد البطاقات.
- اتجاه الواجهة عربي من اليمين إلى اليسار، مع السماح بعرض الوقت والروابط من اليسار إلى اليمين عند الحاجة.

## قواعد الواجهات

- استخدام `ResponsiveInfo` و`ResponsiveContent` من `lib/core/responsive/responsive_layout.dart`.
- تجنب المقاسات الثابتة الكبيرة، وخصوصًا داخل `Row` و`Stack`.
- استخدام `Expanded` و`Flexible` و`Wrap` للنصوص والأزرار المتجاورة.
- إضافة `maxLines` و`TextOverflow.ellipsis` للنصوص القادمة من لوحة التحكم.
- استخدام نسبة عرض إلى ارتفاع للصور والبنرات بدل فرض عرض وارتفاع غير متناسبين.
- استخدام `AdaptiveContentImage` لكل صورة قد تكون ملفًا محليًا الآن أو رابطًا من لوحة التحكم لاحقًا.
- استخدام عدد أعمدة متغير للهاتف والتابلت والويب.
- اختبار كل واجهة على عروض 320 و375 و600 و900 و1200 نقطة.

## قواعد محتوى لوحة التحكم

- يمنع ربط الواجهات الجديدة بقوائم `Map` ثابتة كحل نهائي.
- كل عنصر محتوى يجب أن يملك معرفًا ثابتًا، نوعًا، عنوانًا، حالة نشر، ترتيبًا وبيانات تحديث.
- الصور والصوت والفيديو والبث والملفات والروابط تُمثل بواسطة `ManagedMedia`.
- المحتوى العام القادم من الخادم يُمثل بواسطة `ManagedContent`.
- طبقة التطبيق تتعامل مع `ContentRepository`، ولا تعتمد مباشرة على نوع قاعدة البيانات أو مزود لوحة التحكم.
- تبقى البيانات المحلية الحالية بيانات تجريبية فقط، ويمكن استبدالها لاحقًا بمصدر API دون إعادة بناء الواجهة.

## بنية الوسائط

- `image`: صورة أو غلاف أو بنر.
- `audio`: ملف صوتي قابل للتشغيل.
- `video`: فيديو أو حلقة مرئية.
- `liveStream`: رابط بث مباشر أو إذاعة.
- `file`: كتاب أو مرفق قابل للتنزيل.
- `externalLink`: رابط موقع أو منصة خارجية.

يجب أن تدعم لوحة التحكم الحقول `isActive` و`sortOrder` و`metadata` حتى يمكن إخفاء العناصر وترتيبها وإضافة خصائص جديدة دون تحديث التطبيق لكل تغيير صغير.
